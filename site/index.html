hf2browser

Any Hugging Face LLM → running in your browser, calling your JavaScript functions. WebGPU when the browser has it, plain CPU when it doesn't. No cloud, no server-side inference, no API key.

Try a model in your browser → Download GitHub

Running converted models is the browser-llm-nexus demo's job — chat, tool calls, copy-paste code, no install. hf2browser's job is upstream of that: find a model, convert it, and hand over a URL or a zip you can drop into that page or your own.

Run it

One executable. The Python export pipeline, the CPU verifier and the chat UI are compiled in, so there is nothing to clone and nothing to build:

curl -fsSL https://raw.githubusercontent.com/muthuishere/hf2browser/main/install.sh | sh
hf2browser serve   # opens the UI: search the Hub → convert → chat, all local

Windows (PowerShell):

irm https://raw.githubusercontent.com/muthuishere/hf2browser/main/install.ps1 | iex
hf2browser serve

The installer picks the binary for your platform, checks it against the release SHA256SUMS, and puts it on your PATH. Or take the file straight from Releases — macOS arm64/amd64, Linux amd64/arm64, Windows.

Search with tool-calling detection

Live Hub search flags which models can actually call tools, with download-size estimates before you commit.

One-command conversion

ONNX export + q4 quantization, streamed live. New architectures auto-retry with a modern toolchain.

Verified, not assumed

Every conversion is behaviorally tested on CPU — including whether it really emits schema-valid tool calls.

Then hand it over

One click opens the converted model in the nexus demo, or take the URL, the zip, or a self-contained chat.html elsewhere.

Use it from your own page

The runtime is browser-llm-nexus, a separate standalone package on npm. Where a model comes from is always something you state — nothing is guessed:

import { NexusChat } from 'browser-llm-nexus';

const chat = await NexusChat.load({ hub: 'onnx-community/Qwen3-0.6B-ONNX' }); // Hugging Face
// or { base: '/models/', id: 'Qwen/Qwen3-0.6B' }   — a folder you serve
// or { archive: fileTheUserPicked }                — a portable zip

chat.tool('get_weather', 'Current weather for a city', { city: 'string' },
  async ({ city }) => fetchWeather(city));

console.log(await chat.chat('What is the weather in Chennai?'));
// model emits the tool call → your JS runs → result fed back → grounded answer

One thing worth knowing

Aggressive quantization can destroy tool calling while leaving chat intact. Measured on identical prompts: Qwen2.5-0.5B-Instruct emits no tool calls at q4 or q8 but works at fp16, while the newer Qwen3-0.6B tool-calls fine at q4. That is why every conversion is verified behaviorally rather than assumed — the tool tests the model, then tells you the smallest dtype that actually passes.
